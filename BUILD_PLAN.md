# BUILD PLAN
## AUTONOMI AGENTIC ILMIAH v1.0

The system is built incrementally.

## PHASE 0 — DISCOVERY & ARCHITECTURE
- inspect workspace;
- confirm actual paths;
- document current environment;
- assess existing files;
- identify dependencies;
- confirm architecture.

## PHASE 1 — FOUNDATION
Build:
- centralized path manager;
- configuration loader;
- logging;
- project manager;
- schema validation;
- state management;
- core interfaces;
- basic test harness;
- system bootstrap.

## PHASE 2 — MODEL ROUTING
Build:
- ModelRouter abstraction;
- provider adapters;
- capability-based model selection;
- 9Router integration where applicable;
- connectivity/self-tests.

## PHASE 3 — RESEARCH TOOLS
Build/integrate:
- PublishOrPerish;
- Crossref;
- OpenAlex;
- Semantic Scholar;
- PubMed;
- web search;
- deduplication/normalization.

## PHASE 4 — VERIFICATION ENGINE
Build:
- source state machine;
- existence checks;
- metadata checks;
- DOI checks;
- publisher verification;
- source scoring;
- provenance.

## PHASE 5 — EVIDENCE / CLAIM ENGINE
Build:
- claim registry;
- evidence registry;
- evidence extraction;
- support classification;
- confidence;
- conflict detection.

## PHASE 6 — SYNTHESIS / WRITING
Build:
- synthesis;
- outline;
- writer;
- citation manager;
- reference generation.

## PHASE 7 — AUDIT
Build:
- citation audit;
- fact audit;
- unsupported-claim detection;
- audit reports;
- repair loops.

## PHASE 8 — DOCX
Build:
- DOCX generation;
- formatting templates;
- project finalization;
- output validation.

## PHASE 9 — ACADEMIC WRITING MODE
End-to-end implementation and test.

## PHASE 10 — DEEP RESEARCH MODE
End-to-end implementation and test.

## PHASE 11 — END-TO-END TESTING
Test representative tasks from:
- simple academic writing;
- literature review;
- foundational theory;
- conflicting evidence;
- failed source verification;
- missing evidence.

---

## DEVELOPMENT RULE

Complete and test one phase before relying on it in a later phase.

Do not rebuild completed phases without cause.

Every phase should produce:
- implementation;
- tests;
- documentation;
- status report;
- known limitations;
- next action.
