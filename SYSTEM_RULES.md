# SYSTEM RULES
## AUTONOMI AGENTIC ILMIAH v1.0

## A. WORKSPACE RULES

1. DATA BASE/ is SYSTEM ROOT.
2. Primary system code belongs inside DATA BASE/.
3. TUGAS 1/ and TUGAS 2/ are project workspaces.
4. Never mix unrelated project artifacts.
5. Inspect before modify.
6. Preserve existing files.
7. Avoid destructive operations.
8. Centralize path resolution.

## B. IMPLEMENTATION RULES

9. Prefer modular components.
10. Do not create a monolithic application file.
11. Separate agents from tools.
12. Separate provider adapters from business logic.
13. Prefer explicit interfaces/contracts.
14. Prefer deterministic utilities for deterministic work.
15. Log meaningful state transitions and external calls.
16. Add tests with every significant subsystem.

## C. RESEARCH RULES

17. Candidate != verified.
18. Verified metadata != claim support.
19. Claim support requires evidence from source content.
20. Search multiple sources when warranted.
21. Use dynamic source priority.
22. Preserve foundational sources when justified.
23. Respect user year constraints while allowing justified seminal sources.
24. Record provenance and search history.

## D. VERIFICATION RULES

25. Existence must be verified.
26. Metadata should be corroborated.
27. DOI must never be invented.
28. Publisher information should be checked where practical.
29. Full-text/evidence verification is required for important claims.
30. Conflicting information triggers additional verification or review.

## E. WRITING RULES

31. Writer uses approved claims/evidence.
32. Do not invent references during writing.
33. Do not invent quotations.
34. Do not invent page numbers.
35. Match wording strength to evidence strength.
36. Qualify uncertainty when material.
37. Preserve meaningful disagreement between studies.

## F. AUDIT RULES

38. Every important claim must be auditable.
39. Every citation must map to a source.
40. Every source used in final writing must be verified.
41. Audit failure triggers revision or review.
42. Never mark failed audit as passed.

## G. HUMAN REVIEW RULES

43. Ask for review when a consequential ambiguity cannot be safely resolved.
44. Give structured options.
45. Provide a recommendation where possible.
46. Do not ask unnecessary questions for routine operations.

## H. INTEGRATION RULES

47. Do not claim PoP works until actual test success.
48. Do not claim 9Router works until actual connectivity test success.
49. Do not claim an external API works until actual request/response validation.
50. Preserve raw external results when useful for auditability.
